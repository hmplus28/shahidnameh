# شهیدنامه

**شهیدنامه** یک وب‌اپلیکیشن خالص Python/Django برای ثبت، مدیریت و معرفی زندگی، خاطرات و رسانه‌های مرتبط با شهدا است. رابط عمومی پروژه با **Django Templates** و فایل‌های CSS/JavaScript محلی ساخته می‌شود و هیچ لایه اجرایی Node.js، React یا tRPC ندارد.

## ساختار اجرایی

| مسیر | مسئولیت |
| --- | --- |
| `config/` | تنظیمات، مسیرهای اصلی و نقطه‌های WSGI/ASGI Django |
| `martyrs/` | مدل‌ها، پنل مدیریت، نماها، مسیرها، قالب‌ها و آزمون‌های دامنه شهدا |
| `templates/` | قالب‌های مشترک و صفحه‌های Django Templates |
| `static/` | CSS، JavaScript، Manifest، Service Worker و آیکن‌های PWA |
| `media/` | بارگذاری‌های محلی رسانه در محیط توسعه؛ در تولید باید به ذخیره‌سازی پایدار متصل شود |

## اجرای محلی

ابتدا وابستگی‌های پایتون را نصب و مهاجرت‌ها را اجرا کنید. سپس سرور توسعه Django را آغاز کنید.

```bash
cd shahidnameh
python3 -m pip install -r requirements.txt
python3 manage.py migrate
python3 manage.py createsuperuser
python3 manage.py runserver
```

بخش مدیریت اصلی از نشانی `/panel/` در دسترس است؛ پنل داخلی اختصاصی شهیدنامه با پیشخوان آماری، فهرست پرونده‌ها، فرم‌های فارسی با تقویم جلالی و تاریخچه تغییرات. ثبت، ویرایش و حذف شهدا، خاطرات، تصاویر و ویدئوها از همین پنل انجام می‌شود. پنل استاندارد Django نیز برای کاربر ارشد در `/admin/` برقرار است.

## پنل اختصاصی مدیریت

- **ورود:** نشانی `/panel/login/`؛ هر کاربر دارای «وضعیت کارمند» می‌تواند وارد شود.
- **پیشخوان:** آمار کل محتوا، آخرین پرونده‌ها و آخرین تغییرات.
- **پرونده شهدا:** جست‌وجو و فیلتر (منتشرشده/پیش‌نویس/شاخص)، تنظیم سریع **شهید شاخص** و انتشار، مشاهده در سایت.
- **فرم پرونده:** همه بخش‌ها گروه‌بندی‌شده با انتخابگر تقویم جلالی؛ مدیریت خاطرات، تصاویر و ویدئوهای هر شهید در همان صفحه.
- **نقش‌ها:** نویسنده اجازه کامل ویرایش دارد؛ ناظر فقط مشاهده می‌کند (دکمه‌های تغییر برای او نمایش داده نمی‌شوند).
- **تاریخچه تغییرات:** همه افزودن، ویرایش و حذف‌های انجام‌شده در پنل با نام کاربر ثبت می‌شود.

## پیش‌نمایش پیش از انتشار

هر شهید فیلد **انتشار در سایت** دارد. با برداشتن تیک آن، پرونده از صفحه اصلی، فهرست، جست‌وجو و sitemap حذف می‌شود؛ اما کارکنان (کاربران دارای «وضعیت کارمند») می‌توانند با بازکردن نشانی پرونده آن را با بنر «حالت پیش‌نمایش» ببینند. دکمه **مشاهده در وب‌گاه** در بالای فرم مدیریت هر شهید، پیش‌نمایش زنده را باز می‌کند.

## تاریخچه تغییرات

بخش **تاریخچه تغییرات** در پنل مدیریت، تمام افزودن‌ها، ویرایش‌ها و حذف‌های محتوا را همراه نام کاربر، زمان جلالی و خلاصه تغییرات ثبت و نمایش می‌دهد و فقط قابل مشاهده است.

## سئو

نشانی‌های `sitemap.xml` و `robots.txt` به‌صورت خودکار ساخته می‌شوند. صفحه جزئیات هر شهید متاتگ‌های توضیحات، Open Graph و داده ساختاریافته JSON-LD (نوع Person) دارد تا اشتراک‌گذاری و نمایه‌سازی موتورهای جست‌وجو بهینه باشد.

## نقش‌های پنل مدیریت

گروه‌های **نویسنده** و **ناظر** پس از اجرای مهاجرت‌ها به‌صورت خودکار ساخته می‌شوند. برای همگام‌سازی مجدد آن‌ها در هر زمان، فرمان زیر را اجرا کنید.

```bash
python3 manage.py configure_roles
```

کاربر نویسنده می‌تواند شهدا، خاطرات و رسانه‌ها را ثبت، مشاهده و ویرایش کند؛ اما امکان حذف یا مدیریت کاربران و مجوزها را ندارد. کاربر ناظر فقط می‌تواند این محتوا را مشاهده کند. برای ورود این کاربران به پنل، مدیر باید در صفحه کاربر Django گزینه **وضعیت کارمند** را فعال و گروه مناسب را انتخاب کند.

## داده نمونه

پرونده مستند **شهید دکتر مصطفی چمران** همراه با یک خاطره در `martyrs/fixtures/shahid_chamran.json` آماده شده است. برای بارگذاری آن روی یک پایگاه‌داده تازه:

```bash
python3 manage.py loaddata shahid_chamran
```

## PWA و کارکرد آفلاین

پوسته عمومی شهیدنامه به‌صورت PWA نصب‌پذیر آماده شده است. فایل `static/manifest.webmanifest` نام، رنگ‌ها، آیکن‌ها، میانبرهای جست‌وجو و مدیریت و حالت مستقل اپ را تعریف می‌کند. اسکریپت `static/js/site.js` سرویس‌ورکر را از مسیر ریشه ثبت می‌کند و در مرورگرهای سازگار، کارت «شهیدنامه را نصب کنید» را نمایش می‌دهد.

سرویس‌ورکر در `static/js/service-worker.js` با نسخه کش `shahidnameh-v3` اجرا می‌شود. ابتدا پوسته اصلی شامل صفحه خانه، فهرست، صفحه آفلاین، استایل‌ها، اسکریپت و Manifest را ذخیره می‌کند؛ برای صفحه‌های HTML راهبرد «شبکه در اولویت، کش هنگام قطعی» و برای دارایی‌های هم‌مبدأ راهبرد «کش در اولویت» دارد. پس از هر تغییر در راهبرد کش، نام `CACHE_NAME` را افزایش دهید تا نسخه‌های قدیمی پاک شوند.

## متغیرهای محیطی

در محیط تولید، متغیر `DJANGO_SECRET_KEY` را با یک مقدار تصادفی و محرمانه تنظیم کنید. همچنین `DJANGO_DEBUG=false` و `DJANGO_ALLOWED_HOSTS` را مطابق دامنه‌های مجاز سرور تعیین کنید.

```bash
export DJANGO_SECRET_KEY="یک-کلید-طولانی-و-تصادفی"
export DJANGO_DEBUG=false
export DJANGO_ALLOWED_HOSTS="example.com,www.example.com"
export DJANGO_CSRF_TRUSTED_ORIGINS="https://example.com,https://www.example.com"
```
