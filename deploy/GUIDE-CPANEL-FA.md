# راهنمای گام‌به‌گام استقرار «شهیدنامه» روی هاست cPanel

این راهنما برای میزبانی پروژه روی هاست‌های اشتراکی cPanel (میزبانفا، ایران‌سرور، پارس‌پک و هر هاست دیگری که بخش **Setup Python App** دارد) نوشته شده است. کل فرایند حدود ۱۵ تا ۲۰ دقیقه طول می‌کشد.

> **نکات مهم:**
> 1. اسکریپت استقرار طبق الزام پروژه، فقط و فقط از محیط مجازی (venv) برنامهٔ پایتونی خودِ سی‌پنل استفاده می‌کند و هیچ venv دستی نمی‌سازد؛ پس اول برنامهٔ پایتون را در سی‌پنل بسازید (گام ۴)، بعد اسکریپت را اجرا کنید.
> 2. این پروژه **فقط با MySQL/MariaDB** کار می‌کند (پیش‌فرض خود cPanel). اول دیتابیس را بسازید (گام ۳) — اسکریپت بدون مشخصات کامل دیتابیس ادامه نمی‌دهد و قبل از هر نصبی، اتصال واقعی به MySQL را آزمایش می‌کند.

---

## گام ۱ — پیش‌نیازها

- هاست اشتراکی cPanel با بخش **Setup Python App** (روی CloudLinux تقریباً همه هاست‌ها دارند) و **MySQL® Databases**.
- پایتون ۳.۱۰ یا جدیدتر (گزینهٔ 3.11 یا 3.12 را انتخاب کنید).
- **دیتابیس MySQL/MariaDB** (پیش‌فرض cPanel است و همهٔ هاست‌ها دارند).
- دامنه یا زیردامنه متصل به هاست، **با گواهی SSL** (از بخش SSL/TLS Status گزینهٔ AutoSSL/Let's Encrypt را فعال کنید). اگر SSL فعال نباشد، به‌خاطر کوکی‌های امن، ورود به پنل کار نمی‌کند.
- دسترسی Terminal یا SSH (در cPanel جست‌وجو کنید: Terminal).

## گام ۲ — بردن کد روی هاست

از ترمینال cPanel (یا SSH):

```bash
cd ~
git clone https://github.com/hmplus28/shahidnameh.git
cd shahidnameh
```

اگر دسترسی git ندارید، مخزن را به‌صورت ZIP دانلود و در File Manager آپلود و Extract کنید؛ فقط دقت کنید پوشهٔ نهایی همان چیزی باشد که فایل `manage.py` را مستقیم داخلش می‌بینید.

> **جای پروژه:** می‌توانید پروژه را بیرون از `public_html` (مثلاً در `~/shahidnameh`) نگه دارید — امن‌تر است. اگر مجبورید داخل `public_html` باشد هم مشکلی نیست؛ اسکریپت استقرار به‌طور خودکار فایل `.htaccess` محافظ می‌سازد تا فایل‌های حساس (`.env`، دیتابیس، سورس پایتون و…) از وب قابل دانلود نباشند.

## گام ۳ — ساخت دیتابیس MySQL (الزامی)

این پروژه فقط با MySQL/MariaDB کار می‌کند؛ پس قبل از اجرای اسکریپت، دیتابیس را بسازید:

1. در cPanel بخش **MySQL® Databases** را باز کنید.
2. سه کار انجام دهید:
   - **Create New Database** → مثلاً `shahidnameh` (نام کامل می‌شود `<یوزر-سی‌پنل>_shahidnameh`).
   - **MySQL Users → Add New User** → مثلاً `shahidnameh` با یک رمز قوی (یادداشت کنید).
   - **Add User To Database** → همان یوزر و همان دیتابیس → در صفحهٔ بعد تیک **ALL PRIVILEGES** → **Changes**.
3. این چهار مقدار را برای گام ۶ داشته باشید:

   | کلید در ‎.env‎ | مقدار |
   |---|---|
   | `DB_NAME` | `<یوزر-سی‌پنل>_shahidnameh` |
   | `DB_USER` | `<یوزر-سی‌پنل>_shahidnameh` |
   | `DB_PASSWORD` | همان رمزی که ساختید |
   | `DB_HOST` | `localhost` |

   نام دیتابیس/یوزر را دقیقاً همان‌طور که cPanel نمایش می‌دهد بنویسید (با پیشوند یوزر سی‌پنل).

> اسکریپت استقرار اگر این مقادیر را کامل نیابد یا اتصال به MySQL برقرار نشود، با پیام راهنما متوقف می‌شود و هیچ نصبی انجام نمی‌دهد؛ پس اشتباه در این مرحله مشکلی ایجاد نمی‌کند — فقط اصلاح و دوباره اجرا کنید.

## گام ۴ — ساخت برنامهٔ پایتون (Setup Python App)

1. در cPanel بخش **Setup Python App** را باز کنید و روی **Create Application** بزنید.
2. مقادیر را این‌طور وارد کنید:

   | فیلد | مقدار |
   |---|---|
   | Python version | 3.11 (یا هر نسخهٔ ≥ 3.10) |
   | Application root | `shahidnameh` (همان پوشهٔ پروژه، نسبت به home) |
   | Application URL | دامنه یا زیردامنهٔ شما (بهتر است ریشهٔ دامنه باشد، نه زیرمسیر) |
   | Application startup file | `passenger_wsgi.py` |

3. روی **Create** بزنید. سی‌پنل خودش venv را در مسیری شبیه `~/virtualenv/shahidnameh/3.11` می‌سازد. اسکریپت استقرار این مسیر را **خودکار پیدا می‌کند**.

> **چرا Application URL باید ریشهٔ دامنه باشد؟** استقرار روی زیرمسیر (مثل `example.com/shahidnameh/`) به تنظیمات اضافه (FORCE_SCRIPT_NAME و اصلاح مسیر استاتیک‌ها) نیاز دارد. اگر ناچار به این کار هستید، اول ریشه راه‌اندازی کنید و بعد با پشتیبانی تماس بگیرید.

> اگر برنامهٔ پایتون را با Application root متفاوت ساختید (مثلاً پوشه دیگری)، کافی است هنگام اجرای اسکریپت مسیر venv را بدهید: `bash deploy/deploy_cpanel.sh --venv ~/virtualenv/<نام-پوشه>/<نسخه>`

## گام ۵ — اجرای اسکریپت استقرار

از داخل پوشهٔ پروژه:

```bash
cd ~/shahidnameh
bash deploy/deploy_cpanel.sh
```

اسکریپت به‌ترتیب این کارها را انجام می‌دهد (همهٔ مراحل idempotent هستند و اجرای مکرر مشکلی ایجاد نمی‌کند):

1. پیدا و استفادهٔ venv خود سی‌پنل (اگر پیدا نشد، راهنمای ساخت برنامه را نشان می‌دهد و متوقف می‌شود).
2. ساخت فایل `.env` با کلید امنیتی تصادفی + مقادیر دیتابیس MySQL (اگر موجود نباشد؛ مقادیر موجود هرگز بازنویسی نمی‌شوند).
3. کنترل کامل بودن مشخصات MySQL (اگر ناقص باشد، با راهنمای گام ۳ متوقف می‌شود).
4. نصب وابستگی‌ها (Django، Pillow، whitenoise، درایور MySQL و…).
5. **آزمایش واقعی اتصال به MySQL** (اگر اتصال برقرار نشود، با علت‌های رایج متوقف می‌شود).
6. اجرای مایگریشن‌ها، جمع‌آوری فایل‌های استاتیک، همگام‌سازی نقش‌ها (نویسنده/ناظر).
7. ساخت/به‌روزرسانی `passenger_wsgi.py`.
8. افزودن قواعد امنیتی به `.htaccess`.
9. ری‌استارت برنامه (tmp/restart.txt).

اگر در گام ۳ دیتابیس را هنوز نساخته‌اید، `.env` را طبق گام ۶ کامل کنید و دوباره اجرا کنید.

## گام ۶ — تنظیم دامنه، دیتابیس و مدیر اولیه

1. فایل `.env` را ویرایش کنید (File Manager → Show Hidden Files، یا `nano .env`):

   ```
   DJANGO_ALLOWED_HOSTS=دامنه-شما.ir
   DJANGO_CSRF_TRUSTED_ORIGINS=https://دامنه-شما.ir
   DB_NAME=<یوزر-سی‌پنل>_shahidnameh
   DB_USER=<یوزر-سی‌پنل>_shahidnameh
   DB_PASSWORD=رمز-دیتابیس-از-گام-۳
   DB_HOST=localhost
   DB_PORT=3306
   DJANGO_SUPERUSER_USERNAME=admin
   DJANGO_SUPERUSER_PASSWORD=یک-رمز-قوی
   DJANGO_SUPERUSER_EMAIL=admin@example.com
   ```

2. اسکریپت را دوباره اجرا کنید تا اتصال دیتابیس آزموده، مایگریشن‌ها اجرا و مدیر اولیه ساخته شود:

   ```bash
   bash deploy/deploy_cpanel.sh
   ```

3. در cPanel → Setup Python App دکمهٔ **Restart** را بزنید (یا اسکریپت خودش `tmp/restart.txt` را touch می‌کند).

## گام ۷ — بررسی پس از استقرار

| مسیر | توضیح |
|---|---|
| `https://دامنه-شما/` | صفحهٔ اصلی سایت |
| `https://دامنه-شما/panel/` | پنل مدیریت اختصاصی (مدیریت شهدا، پس‌زمینه‌ها، المان‌ها) |
| `https://دامنه-شما/admin/` | پنل مدیریت جنگو |
| `https://دامنه-شما/robots.txt` | سئو |
| `https://دامنه-شما/sitemap.xml` | نقشهٔ سایت |

**تست شفافیت پس‌زمینه‌ها (مهم):** وارد `/panel/` شوید → بخش پس‌زمینه‌ها → یک تصویر انتخاب/آپلود کنید → مقدار شفافیت (Opacity) را تغییر دهید و ذخیره کنید → صفحهٔ اصلی را باز کنید و تغییر را ببینید. این قابلیت در پنل اختصاصی و هم در `/admin/` در دسترس است.

## دیتابیس MySQL

پروژه فقط با MySQL/MariaDB کار می‌کند و دیتابیس در گام ۳ ساخته می‌شود. چند نکته:

- درایور دیتابیس: پروژه اول `mysqlclient` را امتحان می‌کند؛ روی هاست‌هایی که اجازهٔ کامپایل/gcc ندارند (خطای «Permission denied: 'gcc'» هنگام نصب) اسکریپت **خودکار** درایور `PyMySQL` (پایتون خالص، بدون نیاز به کامپایل) را نصب می‌کند و پروژه با همان کار می‌کند — کاری از شما لازم نیست.
- اتصال، همیشه با `utf8mb4` برقرار می‌شود تا متن فارسی و ایموجی‌ها سالم بمانند.
- اگر بعداً دیتابیس را عوض کردید (مثلاً روی هاست دیگر)، فقط مقادیر `DB_NAME/DB_USER/DB_PASSWORD/DB_HOST/DB_PORT` در `.env` را تغییر دهید، دیتابیس جدید را در cPanel بسازید و `bash deploy/deploy_cpanel.sh` را دوباره اجرا کنید تا مایگریشن‌ها روی دیتابیس جدید اجرا شوند.
- پشتیبان‌گیری: از بخش phpMyAdmin سی‌پنل (Export/Import) استفاده کنید.

## به‌روزرسانی‌های بعدی

```bash
cd ~/shahidnameh
git pull
bash deploy/deploy_cpanel.sh
```

اسکریپت idempotent است: وابستگی‌های جدید نصب، مایگریشن‌های جدید اعمال، استاتیک‌ها جمع و برنامه ری‌استارت می‌شود.

## عیب‌یابی رایج

| نشانه | علت و راه‌حل |
|---|---|
| خطای 503 | معمولاً `passenger_wsgi.py` با پایتون اشتباه اجرا شده. یک بار `bash deploy/deploy_cpanel.sh` را اجرا کنید (برای venv سی‌پنل نسخهٔ بدون re-exec می‌سازد) و در Setup Python App دکمهٔ Restart را بزنید. |
| «محیط مجازی سی‌پنل پیدا نشد» | هنوز برنامهٔ پایتون نساخته‌اید (گام ۴) یا Application root با پوشهٔ پروژه فرق دارد. توجه: venv سی‌پنل بسته به Application root می‌تواند در یکی از این مسیرها باشد: `~/virtualenv/shahidnameh/<نسخه>` یا `~/virtualenv/public_html/shahidnameh/<نسخه>`. اسکریپت هر دو را خودش پیدا می‌کند؛ اگر مسیر دیگری است، پیام خطا فهرست venvهای یافت‌شده را نشان می‌دهد — مسیر را با `bash deploy/deploy_cpanel.sh --venv <مسیر>` بدهید. |
| خطای `/dev/fd/20: No such file or directory` هنگام اجرای اسکریپت | نسخهٔ قدیمی اسکریپت روی سرورهایی که `/dev/fd` ندارند خطا می‌داد؛ با `git pull` آخرین نسخهٔ اسکریپت را بگیرید (رفع شده) یا موقتاً مسیر venv را مستقیم بدهید: `bash deploy/deploy_cpanel.sh --venv ~/virtualenv/public_html/shahidnameh/3.12` |
| «مشخصات دیتابیس MySQL کامل نیست» | گام ۳ را انجام دهید (ساخت دیتابیس و یوزر) و مقادیر `DB_*` را در `.env` کامل کنید؛ سپس دوباره اجرا کنید. |
| «اتصال به MySQL ناموفق بود» | نام دیتابیس/یوزر باید دقیقاً مطابق cPanel باشد (با پیشوند یوزر سی‌پنل)؛ رمز را چک کنید؛ یوزر را با ALL PRIVILEGES به دیتابیس متصل کنید؛ `DB_HOST=localhost` بماند. پیام خطای کامل MySQL بالای همین پیام چاپ می‌شود. |
| خطای نصب mysqlclient («Permission denied: 'gcc'») | نگران نباشید؛ نسخهٔ جدید اسکریپت خودش درایور پایتونِ خالص `PyMySQL` را جایگزین می‌کند. با `git pull` اسکریپت را به‌روز کنید و دوباره اجرا کنید. اگر به هر دلیلی خودکار نصب نشد: در Setup Python App → «Run Pip Install» مقدار `PyMySQL[rsa]` را نصب کنید. |
| صفحه ورود: خطای CSRF | در `.env` مقدار `DJANGO_CSRF_TRUSTED_ORIGINS=https://دامنه-شما` را بگذارید و اسکریپت را دوباره اجرا کنید. |
| ورود پنل کار نمی‌کند و سایت با http است | SSL فعال نیست؛ کوکی‌های امن فقط روی https ارسال می‌شوند. AutoSSL را فعال کنید (یا موقتاً `DJANGO_DEBUG=True`). |
| خطای 500 و صفحهٔ سفید | لاگ را ببینید: `logs` یا در Setup Python App بخش Log. رایج‌ترین علت: فراموش‌کردن `collectstatic` (اسکریپت خودش انجام می‌دهد) یا خراب بودن `.env`. |
| تصاویر آپلودی نمایش داده نمی‌شوند | پوشهٔ `media/` باید قابل نوشتن باشد؛ اسکریپت آن را می‌سازد. اگر دستی کپی کرده‌اید، مجوز 755 بدهید. |
| پایتون قدیمی (3.6/3.8) | حتماً در Setup Python App نسخهٔ 3.10+ را انتخاب کنید؛ پایتون ترمینال cPanel قابل اعتماد نیست و اسکریپت هم از آن استفاده نمی‌کند. |

## امنیت — چه چیزهایی محافظت شده‌اند؟

اسکریپت استقرار یک بلاک `# BEGIN SHAHIDNAMEH-PROTECT` به `.htaccess` اضافه می‌کند که دانلود این‌ها از وب را مسدود می‌کند: `.env`، فایل‌های دیتابیس و پشتیبان‌ها، فایل‌های `.py` و تنظیمات، مستندات، پوشه‌های `.git`، `deploy`، `logs`، `tmp`. فایل‌های عمومی سایت (CSS/JS، فونت‌ها، تصاویر شهدا و پس‌زمینه‌ها، `manifest.webmanifest`) بدون محدودیت سرو می‌شوند.

> دیتابیس MySQL خودش بیرون از دسترس وب است (فقط از طریق phpMyAdmin سی‌پنل)؛ قواعد `.htaccess` لایهٔ محافظت اضافه برای حالتی است که پروژه داخل `public_html` باشد.

> اگر برنامه را خارج از `public_html` می‌گذارید، این قواعد صرفاً لایهٔ احتیاطی‌اند؛ وب به آن پوشه اصلاً دسترسی مستقیم ندارد.
